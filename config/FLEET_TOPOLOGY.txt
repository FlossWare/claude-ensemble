                           DATA FLOW PATTERNS
================================================================================

REQUEST FLOW:                     REPLICATION FLOW:
GitHub/API → LB → Primary         Primary DB → WAL → Standby
  ↓                                  ↓
Route → Queue → Workers           Slot → Memory → Disk
  ↓                                  ↓
Cache/DB → Response               Verification → Sync Confirmation

FAILOVER FLOW:                    CACHE COHERENCY:
Primary Heartbeat Lost               Write → Primary DB → Cache Invalidate
  ↓                                   ↓
Backup Detects (10m)              Propagate to all nodes (async 1s)
  ↓
Promote Backup → Elect New Primary EVENT ARCHIVAL FLOW:
  ↓                                  Hot Events (24h) → Warm Events (90d)
Update Config → Worker Reconnect     ↓
                                     Cold Archive (S3) → Cleanup

================================================================================
                        RELIABILITY & REDUNDANCY
================================================================================

HA STRATEGY:
├─ Active-Passive Control (Primary + Standby)
├─ Active-Active Workers (Horizontal scaling)
├─ Persistent Message Queue (Redis replicated)
├─ Database Replication (Async slot-based)
└─ Distributed Cache (Write-through + fallback)

FAULT TOLERANCE:
├─ Node Failure:       < 1 min recovery (worker pool)
├─ Primary Failure:    < 10 min promotion of backup
├─ Single DB Failure:  < 5 min (read replicas online)
├─ Network Partition:  Consistent state maintained, read-only fallback
└─ Cache Failure:      DB queries increase 4×, queries still succeed

SLOs:
├─ Availability:       99.9% (downtime: ~43 min/month)
├─ Response Time:      p99 < 500ms (cached) or < 2s (DB query)
├─ Data Durability:    99.999% (ACID + WAL + backups)
└─ Recovery Time:      RTO < 10 min, RPO < 1 hour

                              SCALING STRATEGY
================================================================================

HORIZONTAL SCALING (Stateless Workers):
├─ Add server-04, server-05... to worker pool

├─ Current throughput: 5,000 tasks/sec

├─ Sharding strategy: Hash task_id % partition_count
└─ Monitor lag: Consumer lag < 5 min acceptable

├─ In-transit: TLS 1.3 (all connections)

├─ Cache: Plain (internal network, mTLS protected)
└─ Secrets: External vault (HashiCorp Vault)

AUDIT:
├─ All state changes logged (immutable append-only)
├─ User actions tracked (who, what, when)
├─ API requests logged (headers, response code)
├─ Database queries profiled (slow query log)
