## Circuit Breaker Integration

**File:** `shared/circuit-breaker-integration-example.cjs`

**Description:** Demonstrates how circuit breaker protects against failing models during weighted voting and worker orchestration.

**Run:**
```bash
node shared/circuit-breaker-integration-example.cjs
```

**Examples Covered:**
1. Weighted voting with circuit breaker (filters unavailable models)
2. Worker orchestration (pre-flight availability check)
3. Monitoring and recovery (statistics, manual reset)
4. Graceful degradation (fallback chain)
5. All models failed scenario (error handling)

**Key Concepts:**
- Circuit breaker states: CLOSED (healthy) → OPEN (failed) → HALF_OPEN (testing)
- Automatic filtering of unavailable models from voting
- Fallback chains for resilience
- Statistics and monitoring

**Integration Point:**
This is wired into `shared/weighted-voting.cjs` - circuit breaker filtering happens automatically during all voting operations.

## BFT Median Voting

**File:** `shared/example-bft-usage.cjs`

**Description:** Demonstrates Byzantine Fault Tolerance voting strategies for multi-AI consensus with outlier resistance.

**Run:**
```bash
node shared/example-bft-usage.cjs
```

**Examples Covered:**
1. Standard voting vs BFT median (one broken model)
2. MAD outlier detection (audit trail for broken models)
3. Trimmed mean (drop top/bottom 20%)
4. Performance comparison (outlier impact)
5. High-stakes decision (security audit with minority opinion)
6. Edge case: unanimous consensus

**Key Concepts:**
- **median**: Fast, simple, effective (default BFT)
- **mad**: Median Absolute Deviation with audit trail
- **trimmed-mean**: Conservative approach for known outlier count
- Strategies automatically handle broken models returning garbage

**Best Practices:**
- Use `median` for default BFT (fast, simple)
- Use `mad` when you need audit trail of broken models
- Use `trimmed-mean` for high-stakes decisions (security audits)
- Always set `minConfidence` appropriately (default: 20%)

**Integration Point:**
Wired into `shared/weighted-voting.cjs` - pass `strategy: 'median'` or `strategy: 'mad'` in options.

## Model Rotation Policy

**File:** `shared/example-rotation-usage.cjs`

**Description:** Shows how to integrate rotation policy into weighted voting workflows for safe model deployment.

**Run:**
```bash
node shared/example-rotation-usage.cjs
```

**Examples Covered:**
1. Basic integration (register models, record executions)
2. Periodic staleness check (detect models not used in 7 days)
3. Rotation monitoring (status dashboard)
4. Cron job integration (daily maintenance tasks)

**Key Concepts:**
- **Canary stage**: 1% traffic (new experimental models)
- **Ramp stage**: 50% traffic (proven in canary)
- **Full stage**: 100% traffic (production-ready)
- Staleness detection: Force exploration if model unused >7 days
- Thompson Sampling: Learn which models perform best

**Best Practices:**
- Register new models as `canary` (1% traffic)
- Promote to `ramp` after 100 successful executions
- Promote to `full` after 500 successful executions
- Run daily cron job to detect stale models

**Integration Point:**
Wired into `shared/weighted-voting.cjs` - rotation policy auto-applied during voting.

## Consensus Replay

**File:** `shared/consensus-replay-demo.cjs`

**Description:** End-to-end demonstration of replaying historical workflows to measure model improvements over time.

**Run:**
```bash
node shared/consensus-replay-demo.cjs --limit 5
```

**Flow:**
1. Find recent successful workflows (from PostgreSQL)
2. Replay with current models (parallel execution)
3. Compare results (confidence delta, cost delta, duration delta)
4. Generate HTML report (saved to `/tmp/consensus-replay-reports/`)
5. Store to database (`workflow.replays` table)

**Key Metrics:**
- **Verdict**: IMPROVEMENT | NO_CHANGE | DEGRADATION
- **Avg Confidence Delta**: How much confidence changed
- **Arbiter Confidence Delta**: Arbiter-specific improvement
- **Total Cost Delta**: Cost difference (positive = more expensive)

**Use Cases:**
- Validate that model updates improve quality
- Detect regressions in consensus quality
- Measure ROI of model upgrades
- Historical analysis of fleet performance

**Integration Point:**
Uses `shared/consensus-replay.cjs` class. Run as cron job (weekly) to track model quality trends.

## Fleet Executor (Python)

**File:** `shared/fleet_executor.py`

**Description:** Distributed task execution via Python with zero dependencies (stdlib only). Works on ALL architectures (x86_64, arm64, armhf) and Python 3.8+.

**Type:** Feature (not demo)

**Usage:**
```python
from fleet_executor import execute_on_worker

result = execute_on_worker(
    worker='server-01',
    model='gpt-4o-mini',
    task='Analyze this code',
    max_tokens=500,
    max_retries=2,         # Retry on transient failures
    backoff_seconds=1.0    # Exponential backoff (1s, 2s, 4s...)
)

print(result['output'])
print(f"Executed on: {result['execution_host']}")
print(f"Duration: {result['duration_ms']}ms")
```

**Parallel Execution:**
```python
from fleet_executor import execute_on_fleet_parallel

results = execute_on_fleet_parallel(
    workers=['server-01', 'server-02', 'server-03'],
    model='gpt-4o-mini',
    tasks=['Task 1', 'Task 2', 'Task 3'],
    max_retries=2,
    backoff_seconds=1.0
)
```

**Key Features:**
- **Zero dependencies**: Stdlib only (subprocess, json, time, os, re)
- **Cross-platform**: Works on x86_64, arm64, armhf
- **Auto-retry**: Exponential backoff on transient failures (429, 500, 502, 503, 504)
- **Multi-provider**: Supports 10 providers (OpenAI, Anthropic, Google, Groq, Cerebras, Cohere, DeepSeek, OpenRouter, Vertex AI, Ollama)
- **SSH-safe**: Hostname validation prevents command injection

**Provider Support:**
- OpenAI (gpt-4o, gpt-4o-mini, gpt-3.5-turbo)
- Anthropic (claude-3-5-sonnet, claude-3-5-haiku)
- Google (gemini-3.5-flash, gemini-2.5-flash, gemini-2.5-pro)
- Groq (llama-3.3-70b, llama-3.1-70b, mixtral-8x7b)
- Cerebras (llama-3.3-70b, zai-glm-4.7)
- Cohere (command-a-plus, command-r, command-r7b)
- DeepSeek (deepseek-coder, deepseek-chat)
- OpenRouter (25 free models including 550B Nemotron, 405B Hermes)
- Vertex AI (claude models via Google Cloud SDK)
- Ollama (local models: phi3.5, deepseek-r1, command-r, qwen2.5, gemma2)

**Integration Point:**
Used by all workflows that need Python-based task execution (alternative to JavaScript fleet-orchestrator.cjs).

## Known Issues

### Demos Need Updates

The demo files (circuit-breaker-integration-example.cjs, example-bft-usage.cjs, example-rotation-usage.cjs, consensus-replay-demo.cjs) were created as proof-of-concept examples but have not been maintained to match the current API. Known issues:

1. **circuit-breaker-integration-example.cjs**: Calls `resetCircuit()` but circuit-breaker.cjs exports `reset()`
2. **example-bft-usage.cjs**: Missing `await` on `runWeightedVoting()` (it's async)
3. **example-rotation-usage.cjs**: Missing `await` on async functions
4. **consensus-replay-demo.cjs**: May need PostgreSQL schema updates

**Recommendation**: Use these files as **reference documentation** (read the code to understand the concepts), not as runnable demos. The actual features they demonstrate are working and integrated into the system.

### Working Features

The **actual features** are fully functional:
- ✅ **circuit-breaker-provider-extension.cjs**: Imported and used by `monitoring/api-health-monitor.cjs`
- ✅ **fleet_executor.py**: Imported and used by Python-based workflows
