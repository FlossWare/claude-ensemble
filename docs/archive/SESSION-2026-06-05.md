## Pattern Rules (Finalized)

### Core Rules

1. **ALWAYS use parallel()** for both reviews AND solvers
2. **ALWAYS include Gemini** in worker sets (4 models)
3. **DIFFERENT arbiters** when doing review + solve together
4. **Log before/after** parallel operations
5. **Use Read tool**, not Bash commands
6. **export const meta**, not const meta
7. **No import statements** - use inline functions

### Worker Configuration

```javascript
// Default worker set (ALWAYS include Gemini)
const WORKERS = ['opus', 'sonnet', 'haiku', 'gemini']

// Parallel review
log(`🔄 ${WORKERS.length} workers reviewing in parallel...`)
const reviews = await parallel(WORKERS.map(model =>
  () => agent('Review', { label: `${model} Review`, model, schema })
))
log(`✅ Received ${reviews.filter(Boolean).length}/${WORKERS.length} reviews`)
```

### Review + Solve Pattern

```javascript
// REVIEW: Arbiter A
const REVIEW_ARBITER = 'opus'
const reviews = await parallel(WORKERS.map(m => 
  () => agent('Find bugs', { model: m, schema })
))
const reviewDecision = await agent('Select', { model: REVIEW_ARBITER })

// SOLVE: Arbiter B (DIFFERENT!)
const SOLVE_ARBITER = 'sonnet'  // NOT 'opus'!
const fixes = await parallel(WORKERS.map(m => 
  () => agent('Propose fix', { model: m, schema })
))
const solveDecision = await agent('Select', { model: SOLVE_ARBITER })
```

## Key Learnings

### 1. Parallel Execution is Essential
- 3x+ faster than sequential
- Required for arbiter/worker pattern
- User preference: "always use parallel for both reviews and solvers"

### 2. Gemini Provides Value
- 4th perspective catches different issues
- Cost optimization for verification
- User preference: "if gemini is found use it in arbiter/worker pattern"

### 3. Different Arbiters Prevent Bias
- Same arbiter for review + solve creates bias
- Arbiter favors their own review findings
- MUST rotate arbiters between phases

### 4. Role Swap Catches Bugs
- 100% effectiveness (caught 2 critical bugs arbiter missed)
- Arbiter → skeptical worker
- Workers → voting arbiters
- Essential validation step

### 5. Symlinks for Repo Organization
- `~/.claude/repos/` should contain symlinks
- Real repos in proper development locations
- User caught this issue
