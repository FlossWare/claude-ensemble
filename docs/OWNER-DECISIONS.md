# Owner Decisions for Architecture Review

Status: owner confirmation recorded 2026-10-26 for OD-01–OD-04 and OD-06–OD-12. The accepted decisions are the proposed v1 defaults shown below. OD-05 remains the binding v1 scope decision and is not part of this 11-decision confirmation. Owner confirmation does not waive unresolved technical findings or authorize implementation.

Review correction: the public-workflow gap is addressed in the proposed contract by adding Gateway-prefixed Memory/Knowledge record routes and operator-only Gateway rebuild/status/cutover routes. This resolves the missing-entry-point contradiction at the specification level; it does not approve the remaining owner decisions or imply runtime implementation.

| ID | Proposed v1 decision | Why this is the bounded choice | Status |
|---|---|---|---|
| OD-01 | Exact-identifier precedence applies only to candidates returned by retrieval and admitted to Gateway's 100-candidate aggregate pool. It does not promise corpus-wide exact-identifier recall. | The current Index candidate shortlist is bounded and ordered by term-frequency evidence before lexical BM25 ranking. A corpus-wide guarantee requires a separate identifier-aware retrieval path. | Accepted by owner 2026-10-26 |
| OD-02 | Accept the deterministic Index term-frequency shortlist before Lexical Retrieval applies BM25. Do not claim corpus-wide BM25 top-K. | Keeps Index as a bounded representation/lookup service and avoids adding a new ranking algorithm or pagination path to v1. | Accepted by owner 2026-10-26 |
| OD-03 | No pagination, refill, or second retrieval round in v1. A capped or freshness-filtered pool is marked truncated/partial rather than silently refilled. | Makes the 1,500 ms hook budget and candidate bound composable and testable. | Accepted by owner 2026-10-26 |
| OD-04 | No rollback endpoint in v1. Recovery from a bad cutover is a forward rebuild. | Rollback after new writes could lose acknowledged mutations or re-expose tombstoned data unless a second fenced protocol were designed. | Accepted by owner 2026-10-26 |
| OD-05 | Index and retrieval endpoints are internal to the local REST dispatcher by deployment exposure policy. Do not introduce a generalized authentication/principal subsystem for v1. | Preserves the binding one-process REST-only architecture and the decision to defer federation/generalized authentication. Required local deployment restrictions remain in scope. | Binding scope decision; unchanged by 2026-10-26 confirmation |
| OD-06 | One scope per public Gateway request in v1; reject multi-scope fan-out. | Avoids cross-partition aggregation and unbounded per-scope deadline multiplication. | Accepted by owner 2026-10-26 |
| OD-07 | Query expansion is disabled in v1; exactly one original query variant is used. | Removes ambiguity in list identity and candidate-budget accounting. | Accepted by owner 2026-10-26 |
| OD-08 | A rebuild containing any source that cannot be represented under the target profile is ineligible for cutover. No per-source exclusion approval is supported in v1. | Prevents a rebuild from silently omitting canonical data and avoids an underspecified source-specific exclusion-approval protocol. | Accepted by owner 2026-10-26 |
| OD-09 | Provision immutable Index profile bundles from deployment configuration before readiness. There is no implicit built-in `default` bundle. Every write pins `{name, version, digest}`. | Prevents services from guessing component mappings and makes rebuild/profile changes auditable. | Accepted by owner 2026-10-26 |
| OD-10 | Chunking preflight receives the complete pinned Index profile bundle and guarantees deterministic structural and serialized representation bounds only. Provider token limits are declared in the immutable profile and checked by Embedding; provider outages/model failures are asynchronous ingestion failures, never partial publication. | Separates pre-commit size safety from transient provider availability while keeping the preflight bounded and avoiding a multi-service synchronous ingestion chain. | Accepted by owner 2026-10-26 |
| OD-11 | Graph v1 relationship identity is scope + normalized endpoints + relationship type + direction. Directed endpoint order is preserved; undirected endpoint IDs are sorted by Unicode code-point order. Relationship type is NFC-normalized without case folding. Graph computes canonical edge IDs as `rel:` plus SHA-256 of RFC 8785 canonical JSON; source-local edge IDs remain per-support provenance. Exact label/alias matching resolves extracted entity mentions to graph nodes. | Makes multi-source support and deletion semantics deterministic without adding a separate entity-resolution service. | Accepted by owner 2026-10-26 |
| OD-12 | Learning v1 maps `success` to reward 1 and `failure` to reward 0 under `binary-reward-v1`, using typed `explicit_user_feedback` evidence whose asserted result must match the outcome. Thompson v1 uses `beta-bernoulli-v1` with Beta(1,1) priors and the named `system-csprng-v1` randomness policy; same idempotency key returns the persisted selection, while different keys may produce different valid samples. | Provides a concrete initial contract without promising cross-implementation bit-for-bit randomness. Alternative reward models or priors require a new version and fixtures. | Accepted by owner 2026-10-26 |
